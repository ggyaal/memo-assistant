# Memo Assistant — MVP 제품 명세 v0.1

## 1. 배경과 단계별 목표

### Phase 1 — AX School 과제 제출 (이번 범위)
여러 사용자가 닉네임을 입력하고 **공개 메모**를 작성한다. Flue 에이전트가 입력에서 항목을 추출·정리·분류·일정 해석·알림 추천 판단을 수행한 뒤 **Tool Calling으로 D1에 저장**한다. 사용자는 오늘의 메모 및 전체 공개 메모를 열람한다.

### Phase 2 — 사용성 및 워크플로 검증
샘플 입력과 피드백으로 분류·날짜 해석·도구 호출 성공률을 측정하고 개선한다.

### Phase 3 — 개인 기억 에이전트
인증, 개인/공유 데이터 분리, 자연어 검색, 수정/삭제, 실제 알림, 브리핑을 도입한다.

### Phase 4 — 서비스 개발
음성 입력, UX, 백업·운영·보안·확장성 고도화. 현 기술 스택 유지 여부는 재평가.

## 2. 이번 MVP 요구 기능

### 필수 (P0)
- 닉네임 입력(비로그인 게스트, 작성자 표시 용도에 한함)
- 공개 범위 안내 + 민감정보 입력 금지 문구
- 텍스트 입력, 전송 중 상태, 오류 표시
- 하나의 입력을 1개 이상 독립 메모로 분석·분리
- 메모 분류: `todo`, `schedule`, `idea`, `note`
- 제목/요약/원문 연결, 일정·기한 추출, 알림 추천 여부(+ 추천 사유, 실제 발송 아님)
- Flue 에이전트에서 등록 Tool을 통해 D1 영구 저장
- 최근 공개 메모 목록, **오늘 등록한 메모** 목록, 작성자 닉네임 표시
- 메모 생성 시각과 일정 날짜를 구분; 한국 시간으로 표시
- 기본 입력 검증/예외 대응, AI 요청 남용 최소 방지
- 공개 GitHub README: 대상 사용자/대신하는 업무, 구현/미구현 기능, 로컬 실행 방법

### 가능하면 추가 (P1)
- 작성자별 필터, 종류별 필터
- AI 결과를 사용자가 👍/👎로 평가(평가 기록 저장, 자동 학습 아님)
- 하루 AI 호출 사용량 또는 간단한 서버 측 요청 제한

### 이번에 하지 않을 것 (P2)
- 음성 인식/STT, 실제 알림 전송, 캘린더 연동
- 로그인, 개인 메모, 권한별 공개 범위
- 자연어 기억 검색, 메모 수정·삭제, 복잡한 관리자 화면
- 별도 Python 백엔드, 벡터 DB, 멀티에이전트

## 3. 사용자 시나리오
1. 웹에 접속 → '모든 입력은 공개됩니다' 안내 확인 → 닉네임 설정.
2. 입력: `오늘 장 보고, 내일 오후 3시에 병원 예약해야 해. AI 검색 기능 아이디어도 메모해 줘.`
3. Flue 에이전트가 `todo` 및 `idea` 등으로 의미 단위 분리, 일정 추출. 한국 날짜 기준으로 상대 날짜 해석.
4. Tool이 원본 `source` 1건과 연결된 메모 여러 건을 저장.
5. 성공 시 정리된 카드 목록 반환. 화면의 `오늘 등록된 메모` / `전체 공개 메모`에 즉시 반영.
6. 다른 브라우저에서도 메모 목록이 보임. 단, 닉네임만으로 본인 확인/소유권을 주장하지 않음.

## 4. AI 출력 계약 (예시; 실제 구현 시 스키마 검증)
```json
{
  "memos": [
    {
      "title": "장보기",
      "content": "오늘 장보기",
      "category": "todo",
      "due_at": null,
      "due_text": "오늘",
      "reminder_recommended": true,
      "reminder_reason": "오늘 해야 할 일로 언급됨"
    },
    {
      "title": "병원 예약",
      "content": "내일 오후 3시에 병원 예약하기",
      "category": "todo",
      "due_at": "<요청 당시 KST 날짜 기준 다음 날 15:00의 ISO-8601>",
      "due_text": "내일 오후 3시",
      "reminder_recommended": true,
      "reminder_reason": "명확한 수행 시각이 언급됨"
    },
    {
      "title": "AI 검색 기능",
      "content": "AI 검색 기능 추가 아이디어",
      "category": "idea",
      "due_at": null,
      "due_text": null,
      "reminder_recommended": false,
      "reminder_reason": null
    }
  ]
}
```

메모의 `due_at`은 실제 일정의 시간이다. `created_at`과 혼동하지 않는다. '다음에', '언젠가' 등 불명확한 표현을 정확한 날짜로 조작하지 않는다. 일정 자체와 알림을 보내는 작업은 다르다.

## 5. 최소 데이터 구조 (D1)

### `sources` (원본 입력)
- `id` TEXT PRIMARY KEY
- `nickname` TEXT NOT NULL
- `raw_text` TEXT NOT NULL
- `request_id` TEXT NOT NULL UNIQUE (중복 요청 방지)
- `created_at` TEXT NOT NULL (UTC ISO 8601)

### `memos` (분리된 메모)
- `id` TEXT PRIMARY KEY
- `source_id` TEXT NOT NULL REFERENCES sources(id)
- `title` TEXT NOT NULL
- `content` TEXT NOT NULL
- `category` TEXT NOT NULL
- `due_at` TEXT NULL (UTC ISO 8601, 정확한 일정일 때)
- `due_text` TEXT NULL (원문에서 언급한 기한 표현)
- `reminder_recommended` INTEGER NOT NULL DEFAULT 0
- `reminder_reason` TEXT NULL
- `created_at` TEXT NOT NULL

실제 DB에는 조회 패턴에 맞는 인덱스를 추가한다. 첫 저장 시 원본 1건과 분리 메모 N건의 일관성을 유지하며, 요청 재시도로 중복 생성되지 않게 한다. 모호한 일정은 `due_at = null`로 보관한다.

## 6. API/Flue 설계 원칙
- `GET /api/memos?scope=today|all` : 생성일 기준 오늘(KST) / 전체 공개 목록, 페이지네이션 및 최대 반환 개수 제한.
- 메모 생성은 Flue Agent 호출 경로를 통해 진행. 인증/입력 크기 검증은 **에이전트 접수 전에** 수행.
- 가능하면 `save_memos` Flue Tool이 직접 D1 저장 로직을 호출. 프레임워크 런타임 제약이 있다면 공식 패턴으로 구현하고 구조를 문서화.
- AI에게 `nickname`, `request_id`, `source_id`, `created_at` 등 신뢰해야 하는 필드의 생성/변조를 맡기지 말 것. 서버가 지정.
- 클라이언트는 모델이 돌려준 문자열을 HTML로 렌더링하지 말 것.
- 입력 제한(예: 1,000자), 닉네임 길이 제한, 모델 응답 개수 제한 등은 서버에서도 검증.
- 메모 목록은 **공개 게시판** 개념이다. 개인/비밀 메모인 것처럼 표현하지 않는다.

## 7. 화면 (모바일 우선)
- 상단: Memo Assistant / 공개 체험 안내
- 시작: 닉네임 입력
- 입력 카드: 여러 생각을 한 번에 입력할 수 있는 textarea + 'AI로 정리하기'
- 결과 카드: 항목별 분류, 제목, 내용, 일정·기한, 알림 추천 배지
- 목록 탭: '오늘 등록된 메모' / '전체 공개 메모'
- 빈 상태/로딩/실패/무료 할당량 초과 메시지
- 피드백 버튼은 시간 남으면 구현

## 8. 수용 테스트
- 하나의 입력에서 서로 다른 주제 3개가 분리된다.
- 기한 없는 아이디어는 임의의 날짜를 갖지 않는다.
- `내일 오후 3시`가 요청 당시 한국 날짜 기준으로 정확히 해석된다.
- 같은 `request_id` 재요청 시 중복 저장되지 않는다.
- 서로 다른 브라우저에서 공개 메모가 동일하게 조회된다.
- 원본 텍스트 및 각 메모의 source_id 연결을 확인할 수 있다.
- 모델 오류, DB 오류, 요청 한도 초과 시 사용자에게 오류가 표시된다.
- 실제 알림·음성·로그인 등이 구현된 것처럼 README에 표시되지 않는다.
