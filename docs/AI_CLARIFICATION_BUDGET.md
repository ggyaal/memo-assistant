## 3. 호출 경로 — 기존 vs 개선
```text
기존: 입력 → (AI 1회) save_memos가 바로 D1 저장 → 알림 자동 예약
개선: 입력 → (AI 1회) save_memos가 서버 규칙으로 질문 필요 여부 판단
        ├─ 질문 없음 → 기존과 똑같이 바로 저장 (201)
        └─ 질문 있음 → 초안(memo_drafts, 30분)만 저장 (202, 메모·알림 없음)
              → 버튼/날짜·시각 선택 · 건너뛰기 · 추가 질문 안 하기 (모두 AI 0회)
              → commit 1회: sources/memos 저장 → 알림 자동 예약
              → 저장 취소: 초안만 닫힘, 저장·알림 없음
```
질문은 모델이 만들지 않고 **서버 규칙**(`src/shared/clarify.ts`)이 저장 문구로 만듭니다. 그래서 출력 토큰(비용의 대부분)이 늘지 않습니다.

## 5. 하루 처리량 (가정 명시)
- 가정: 메모 정리 1회 실측 평균 ≈ 32–34 Neurons(1턴), 가끔 2턴 ≈ 78. 음성은 하루 30분 상한(≈ 1,400).
- 무료 10,000 중 음성 1,400을 빼면 메모 정리에 약 8,600. 1턴 평균이면 약 250회, 모두 2턴이면 약 110회.
- 앱 상한은 **150회 또는 예상 6,000 Neurons 중 먼저 닿는 쪽**입니다. 예상식은 15–25자 입력에서 36–40으로, 1턴 실측(24–44)보다 약간 크고 2턴(78)보다 작습니다. 그래서 예상 6,000은 실측으로 약 5,000–6,000이고, 나머지(≥ 2,600)가 2턴·로컬 개발·재시도의 여유분입니다.
- 1사용자 세션: 명확한 입력 1건 ≈ 34, 확인 질문이 있는 입력 1건 ≈ 34(질문·답변 0). 음성 10초 추가 시 ≈ +8.

## 6. 예산이 적을 때 동작
- 하루 상한(횟수·예상 Neurons)이나 분당 제한에 걸리면 AI를 부르기 **전에** 429와 안내 문구를 돌려줍니다. 입력한 글은 화면에 남습니다.
- 이미 만든 **초안의 확정·답변·취소는 AI가 필요 없으므로 예산이 바닥나도 계속 됩니다**(초안을 잃지 않음).
- Cloudflare 무료 할당량을 넘으면 모델 호출이 4006으로 실패하고, 앱은 "오늘 무료 사용량을 모두 썼습니다"로 안내합니다.

## 7. Cloudflare 대시보드 vs 앱 표시
- 대시보드: 계정 전체의 실제 Neurons(운영 + 로컬 `npm run dev` + 음성 + 실패 호출 포함).
- 앱 "실측": 운영 Worker의 **메모 정리 응답 토큰**만 공식 단가로 환산한 값입니다. 음성·로컬 개발·응답을 받지 못한 호출은 빠집니다.
- 앱 "예상"과 "%": 요청 전 차감한 추정치입니다. 실패·취소도 포함되므로 실측보다 클 수 있습니다.

## 8. 측정 방법과 재현
- 에이전트가 `useResponseFinish`로 응답 전체(모든 턴)의 `usage.input/output`을 메타데이터에 붙이고, 서버가 `neuronsFromTokens`로 환산해 기록하고 `{"event":"ai_usage",...}`로 로그에 남깁니다.
- 재현: `npm run dev`(실제 AI, 무료 Neuron 사용) → 같은 6개 입력을 `POST /api/memos`(JSON)로 보냄 → dev 로그에서 `ai_usage` 줄 확인 → 초안은 `POST /api/memo-drafts/:id/commit`로 확정하고 `ai_usage` 줄이 늘지 않는지 확인.
- 한계: 입력당 1–2회, 로컬에서 측정(운영과 같은 모델·지시문). 모델 출력 길이는 실행마다 달라지며, 2턴이 되는 빈도는 측정하지 않았습니다.
